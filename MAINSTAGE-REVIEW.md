# NextPhase · MainStage review build

This isolated prototype implements the first weekly-study slice from the [MainStage Integration Review](../NextPhase-Planning/07-MainStage-Integration-Review.md) and [Weekly Study Integration Assessment](../NextPhase-Planning/08-Weekly-Study-Integration-Assessment.md). The production data reference is HomeGroups at commit **1e31cc4dd984adc638db2aa87571618fee1f3e31**. App code is in **index.html**, **styles.css**, **app.js**, **corpus.js**, and **fellowship.js**.

## Explore

- Open the root for the current study. Read the daily passage, choose a different day or week, or expand Weekly Scripture, Study guide, and Listen. A link like **?week=6** opens that portion. The original three named study aliases are recognized via **?study=bereshit**, **?study=noach**, and **?study=lech-lecha**.
- Open a verse number to reach its tools. Back returns to the previous panel; Close returns to the original screen. Browser Back and Escape work for nested excursions. Open panels can be expanded. Changing the passage inside the reader leaves the chosen study and discussion intact.
- Open Study discussion for the reverse 3D face. Try a reply with a Scripture attachment, open that attachment, and close it to return to the discussion. Private conversations are member excursions from the reverse. Discussion archives show the selected study by year and are read-only. Week 1, Week 6, and the current week have sample content; other weeks can start with an empty local thread.
- The prototype stores notes, drafts, and demo posts in this browser's local storage. It sends no messages and has no sign-in, member authorization, shared database, analytics or Firebase. Use sample text when reviewing.

## Schedule and open decisions

The historical engine uses a fixed Saturday UTC anchor and a two-week offset in a repeating 52-week cycle. The day displayed by MainStage follows the device's local weekday, with Sunday as day 1. As in the source, the two boundaries may change at different local times. The date is evaluated at launch. Confirm the expected time zone, rollover behavior in a long-running session, and whether the UTC boundary is intentional before production adoption.

The daily and weekly CSVs also include two supplemental rows beyond the regular 52-week engine. They appear only under Calendar studies. No annual date assignment, holiday override, combined-portion rule or rollover rule was inferred for those rows. Annual discussion history uses the device-local **civil year** as a prototype partition. The product still needs a decision on civil year versus cycle year, the canonical association when a portion repeats, and trusted discussion period boundaries.

The source repository's own license is retained in **corpus/LICENSE**. Review the separate terms for third-party translations, editorial material and recordings before any broader distribution. The external playback and viewer links need their own device and provider checks.

## Run or check locally

Serve the repository root over HTTP. For example, from this folder use **python -m http.server 8000** and open **http://localhost:8000**. The implementation needs no build or runtime package. **node check.cjs** runs the browser checks when Playwright and its Chromium are installed. The check also supports **NEXTPHASE_PLAYWRIGHT**, **NEXTPHASE_CHROME**, and **NEXTPHASE_SCREENSHOTS** environment overrides for an existing browser installation and screenshot output folder.
